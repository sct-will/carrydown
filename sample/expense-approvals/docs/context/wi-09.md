Bundle format 1. Sources: architecture 0.3 (reviewed).
Downstream use: approved for implementation in this repository's code and tests. Not for quoting in issue text. Evidence may include response bodies with synthetic data only.

## Obligations

### architecture 3.6 Deployment

The service runs as one container behind the company gateway, in three environments: test, staging and production. Database migrations only move forward. The export job runs at 02:00 UTC and writes to the ledger drop folder. The whole feature sits behind the flag EXPENSE_APPROVALS_ENABLED (section 5.1). With the flag off the service starts, answers its health check and refuses every other request with the status 404.

### architecture 4.2 GOV-2 Audit and retention

Owner: internal audit. Applies to every table named below.

1. Every state change of a report writes one audit_event in the same database transaction. If the audit write fails, the change fails.
2. The audit table is append only. The application account has insert and select rights on it and no update or delete right.
3. An audit_event records who, when, what changed (from_state and to_state), and a small detail object. It holds identifiers, never names, receipt contents or email addresses.
4. Reports, line items, approval steps and audit events are kept for 7 years from the decision date. Receipt files are kept as long as their report.
5. Deletion happens only by a retention job after the 7 years, and never for a report under a legal hold.
6. Log lines carry report identifiers and event types. They never carry amounts, comments or receipt contents.
7. Reading the audit trail of a report is itself recorded as an audit_event of type audit.viewed.

### architecture 7.3 Ledger export file

One file per night, named `expenses-YYYYMMDD.csv`, with a second file `expenses-YYYYMMDD.sha256` that holds the SHA-256 checksum of the first. One row per approved line item of every report that moved to Approved since the last export. After writing, the job moves those reports to Exported.

| Column | Meaning |
| --- | --- |
| report_id | UUID of the report |
| line_item_id | UUID of the line item |
| employee_id | Submitter |
| cost_center | Cost center of the submitter at approval time |
| spent_on | Date of the expense, YYYY-MM-DD |
| category | Category code |
| amount_cents | Amount in the line currency, integer |
| currency | ISO 4217 currency code |
| base_amount_cents | Amount in USD, integer |
| approved_at | UTC timestamp of the last approval |
