## Obligations

### architecture 5.1 DS-1 Delivery standard

Owner: the platform engineering team. Applies to every pull request.

1. Feature flag. All new behavior sits behind EXPENSE_APPROVALS_ENABLED, off by default. With the flag off, nothing observable changes except the health check.
2. Tests. `npm test` runs the unit tests. `npm run test:contract` runs the contract tests against `contracts/openapi.yaml`. Both pass before a pull request merges.
3. Lint. `npm run lint` passes with no warnings.
4. Contracts first. `contracts/openapi.yaml` is the interface between the Workflow track and the Experience track. A change to it is its own pull request, announced at the next checkpoint.
5. Migrations. `npm run migrate` applies migrations. They only move forward. Each has a test that runs it on an empty database and on a copy of the previous schema.
6. Errors. Every error response uses the envelope of section 7.1.
7. Pull requests stay under 400 changed lines where possible. The description lists the acceptance criteria and the proof for each.
8. Commit messages are in the imperative mood. Secrets and personal data never appear in code, tests, logs or fixtures.

### architecture 8.1 Risks

| Id | Risk | Response |
| --- | --- | --- |
| R1 | The reporting line data is out of date, so routing picks the wrong manager. | Routing reads the line once at submit time and records it. Finance can ask for a re-route. |
| R2 | Managers ignore reminders and reports pile up. | Escalation after 5 business days (section 3.5). The pilot measures time to decision. |
| R3 | The export format changes after finance review. | The file format sits in one module and a contract test. The stakeholders own the sign-off. |
| R4 | Receipts hold personal data. | Receipt store keys are random. Receipts are never logged or put in events (GOV-2). |
| R5 | The two tracks drift on the API. | Contracts first (DS-1.4) and a joint check at every checkpoint. |
