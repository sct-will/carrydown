# Approved context for WI-04, Approver inbox and decisions

Bundle format 1. Sources: architecture 0.3 (reviewed).
Downstream use: approved for implementation in this repository's code and tests. Not for quoting in issue text. Evidence may include response bodies with synthetic data only.

## Obligations

### architecture 2.1 Functional requirements

| Id | Requirement |
| --- | --- |
| FR-1 | A submitter creates a draft report with line items. Each line has a date, category, amount, currency, merchant and note. |
| FR-2 | A submitter attaches receipts to a report. Allowed types are PDF, PNG and JPEG. Each file is at most 10 MB. A report holds at most 20 receipts. |
| FR-3 | A submitter submits a draft. A submitted report cannot be edited, only returned by an approver. |
| FR-4 | The service routes a submitted report to approvers by the rules in section 3.5. |
| FR-5 | An approver sees an inbox of the reports waiting for their decision, oldest first. |
| FR-6 | An approver approves, rejects or returns a report, and must give a comment when rejecting or returning. |
| FR-7 | The submitter is notified of each decision and each state change. |
| FR-8 | An approver names a delegate for a range of dates. The delegate sees the approver's inbox for that range. |
| FR-9 | Approved reports are exported to the ledger every night in the file format of section 7.3. |
| FR-10 | An auditor reads the full trail of any report. |

### architecture 3.4 Report lifecycle

| From | Event | To | Who may cause it |
| --- | --- | --- | --- |
| Draft | submit | Submitted | Submitter |
| Submitted | routed | In approval | Service |
| In approval | approve (last step) | Approved | Approver or delegate |
| In approval | approve (not last step) | In approval | Approver or delegate |
| In approval | reject | Rejected | Approver or delegate |
| In approval | return | Returned | Approver or delegate |
| Returned | submit | Submitted | Submitter |
| Approved | export | Exported | Export job |

Rejected and Exported are final. Any other transition is refused with the error code E_STATE.

### architecture 6.1 What people asked for

| Id | Finding |
| --- | --- |
| BA-1 | Submitters want to start a report on a phone and finish it on a laptop. Drafts must be saved without a submit. |
| BA-2 | Managers decide in the gaps of their day. They want one inbox, the oldest report first, with the total and the submitter visible without opening it. |
| BA-3 | Finance wants one line in the ledger file per approved line item, with the cost center, so nobody splits totals by hand. |
| BA-4 | Managers on leave leave reports waiting. A delegate for a date range fixes most of it. |
| BA-5 | Submitters want to know why a report was returned. A comment is not optional on a return. |
| BA-6 | Finance wants reminders early. Two business days is their preference. |

### architecture 7.1 REST API

All paths start with `/v1`. All bodies are JSON. The caller's identity comes from the gateway header `X-Employee-Id`, which the gateway sets and clients cannot forge.

| Method and path | Purpose | Success |
| --- | --- | --- |
| POST /reports | Create a draft report. | 201 with the report |
| GET /reports/{id} | Read a report with line items, receipts and steps. | 200 |
| PUT /reports/{id} | Replace the line items of a draft or returned report. | 200 |
| POST /reports/{id}/receipts | Upload a receipt (multipart form). | 201 with the receipt |
| POST /reports/{id}/submit | Submit a draft or returned report. | 202 with the state |
| GET /inbox | List the reports waiting for the caller, oldest first. | 200 with a page |
| POST /reports/{id}/decisions | Approve, reject or return. | 200 with the report |
| PUT /delegates | Create or replace the caller's delegate record. | 200 |
| GET /reports/{id}/audit | Read the audit trail (auditors only). | 200 with a page |

Decision request.

```json
{ "decision": "approve", "comment": "" }
```

`decision` is `approve`, `reject` or `return`. `comment` is required and not blank for `reject` and `return`.

Error envelope used by every endpoint.

```json
{
  "error": {
    "code": "E_FORBIDDEN",
    "message": "GOV-1.3 refused this decision: the approver already decided an earlier step.",
    "rule": "GOV-1.3",
    "request_id": "9f0c1c0e-6a52-4c0f-b3a6-6d3a1a2c9a10"
  }
}
```

| Code | Status | Meaning |
| --- | --- | --- |
| E_VALIDATION | 400 | The body or a field fails its rule. The message names the field. |
| E_FORBIDDEN | 403 | A governance rule or a role check refused the call. `rule` names the rule. |
| E_NOT_FOUND | 404 | The report does not exist or the caller may not know it exists. |
| E_STATE | 409 | The transition is not allowed from the current state (section 3.4). |
| E_LIMIT | 422 | The base total is above 25,000.00 and cannot be routed. |
