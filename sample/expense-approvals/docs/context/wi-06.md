# Approved context for WI-06, Approval limits and separation of duties

Bundle format 1. Sources: architecture 0.3 (reviewed).
Downstream use: approved for implementation in this repository's code and tests. Not for quoting in issue text. Evidence may include response bodies with synthetic data only.

## Obligations

### architecture 3.5 Routing

The routing engine builds the steps when a report moves from Submitted to In approval. It uses the base total of the report.

| Base total (USD) | Steps in order |
| --- | --- |
| Up to 500.00 | Line manager |
| 500.01 to 5,000.00 | Line manager, department head |
| 5,000.01 to 25,000.00 | Line manager, department head, finance reviewer |
| Above 25,000.00 | Not routed. The service returns E_LIMIT and the submitter follows the offline exception process. |

Rules that apply to every route.

1. If an approver in a step is the submitter, that step moves to the next person up the reporting line.
2. Steps are decided in order. A later step does not see the report until the earlier step approves.
3. A reminder goes to the current approver after 3 business days without a decision. After 5 business days the step escalates to the next person up the reporting line, and the audit trail records the escalation.
4. The routing result is stored as approval_step rows and does not change after routing, except by escalation.

### architecture 4.1 GOV-1 Approval limits and separation of duties

Owner: the finance policy team. Applies to every decision, in every environment.

1. Nobody approves, rejects or returns their own report, directly or as a delegate.
2. An approver must stand above the submitter in the reporting line, or be a finance reviewer.
3. The people in the steps of one report must all be different people.
4. A delegate may act only for dates inside the delegate record, and never on a report that the delegator submitted.
5. Limits per step. A line manager's approval counts only for a base total up to 5,000.00. A department head's approval counts up to 25,000.00. Nothing above 25,000.00 can be approved in the service (section 3.5).
6. A refused decision returns the error code E_FORBIDDEN, names the rule number (for example GOV-1.3) and changes nothing.
7. The rules module applies these checks on the server for every decision. The web client may hide a button, but it is never the control.

### architecture 7.1 REST API

All paths start with `/v1`. All bodies are JSON. The caller's identity comes from the gateway header `X-Employee-Id`, which the gateway sets and clients cannot forge.

| Method and path | Purpose | Success |
| --- | --- | --- |
| POST /reports | Create a draft report. | 201 with the report |
| GET /reports/{id} | Read a report with line items, receipts and steps. | 200 |
| PUT /reports/{id} | Replace the line items of a draft or returned report. | 200 |
| POST /reports/{id}/receipts | Upload a receipt (multipart form). | 201 with the receipt |
| POST /reports/{id}/submit | Submit a draft or returned report. | 202 with the state |
| GET /inbox | List the reports waiting for the caller, oldest first. | 200 with a page |
| POST /reports/{id}/decisions | Approve, reject or return. | 200 with the report |
| PUT /delegates | Create or replace the caller's delegate record. | 200 |
| GET /reports/{id}/audit | Read the audit trail (auditors only). | 200 with a page |

Decision request.

```json
{ "decision": "approve", "comment": "" }
```

`decision` is `approve`, `reject` or `return`. `comment` is required and not blank for `reject` and `return`.

Error envelope used by every endpoint.

```json
{
  "error": {
    "code": "E_FORBIDDEN",
    "message": "GOV-1.3 refused this decision: the approver already decided an earlier step.",
    "rule": "GOV-1.3",
    "request_id": "9f0c1c0e-6a52-4c0f-b3a6-6d3a1a2c9a10"
  }
}
```

| Code | Status | Meaning |
| --- | --- | --- |
| E_VALIDATION | 400 | The body or a field fails its rule. The message names the field. |
| E_FORBIDDEN | 403 | A governance rule or a role check refused the call. `rule` names the rule. |
| E_NOT_FOUND | 404 | The report does not exist or the caller may not know it exists. |
| E_STATE | 409 | The transition is not allowed from the current state (section 3.4). |
| E_LIMIT | 422 | The base total is above 25,000.00 and cannot be routed. |

## Conflict resolution that applies

- Section 3.5 puts a line manager first on routes up to 25,000.00, while GOV-1.5 says a line manager counts only up to 5,000.00. Read "counts" as the approval that completes the report. Refuse an approve with GOV-1.5 when the last step approver's role limit is below the total, and always above 25,000.00. The ground truth gives the finance reviewer no limit, so use 25,000.00. Confirm with the finance policy team.
- GOV-1.3 and a delegate. Treat the person who acts as the person in the step, so a delegate who holds another step of the same report is refused.
