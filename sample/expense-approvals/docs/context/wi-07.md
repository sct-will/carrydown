# Approved context for WI-07, Audit log and retention

Bundle format 1. Sources: architecture 0.3 (reviewed).
Downstream use: approved for implementation in this repository's code and tests. Not for quoting in issue text. Evidence may include response bodies with synthetic data only.

## Obligations

### architecture 3.3 Data model

All identifiers are UUIDs. All timestamps are UTC. Amounts are integers in minor units (cents). A fixed rate table, maintained by finance and loaded as data, converts a line item currency to the base currency (USD).

| Table | Key fields |
| --- | --- |
| report | id, submitter_id, state, base_total_cents, submitted_at, decided_at, version |
| line_item | id, report_id, spent_on, category, amount_cents, currency, base_amount_cents, merchant, note |
| receipt | id, report_id, line_item_id (optional), object_key, content_type, size_bytes, sha256 |
| approval_step | id, report_id, position, role, approver_id, state, decided_at, comment |
| delegate | id, approver_id, delegate_id, starts_on, ends_on |
| audit_event | id, occurred_at, actor_id, report_id, event_type, from_state, to_state, detail (JSON) |

### architecture 4.2 GOV-2 Audit and retention

Owner: internal audit. Applies to every table named below.

1. Every state change of a report writes one audit_event in the same database transaction. If the audit write fails, the change fails.
2. The audit table is append only. The application account has insert and select rights on it and no update or delete right.
3. An audit_event records who, when, what changed (from_state and to_state), and a small detail object. It holds identifiers, never names, receipt contents or email addresses.
4. Reports, line items, approval steps and audit events are kept for 7 years from the decision date. Receipt files are kept as long as their report.
5. Deletion happens only by a retention job after the 7 years, and never for a report under a legal hold.
6. Log lines carry report identifiers and event types. They never carry amounts, comments or receipt contents.
7. Reading the audit trail of a report is itself recorded as an audit_event of type audit.viewed.

### architecture 7.1 REST API

All paths start with `/v1`. All bodies are JSON. The caller's identity comes from the gateway header `X-Employee-Id`, which the gateway sets and clients cannot forge.

| Method and path | Purpose | Success |
| --- | --- | --- |
| POST /reports | Create a draft report. | 201 with the report |
| GET /reports/{id} | Read a report with line items, receipts and steps. | 200 |
| PUT /reports/{id} | Replace the line items of a draft or returned report. | 200 |
| POST /reports/{id}/receipts | Upload a receipt (multipart form). | 201 with the receipt |
| POST /reports/{id}/submit | Submit a draft or returned report. | 202 with the state |
| GET /inbox | List the reports waiting for the caller, oldest first. | 200 with a page |
| POST /reports/{id}/decisions | Approve, reject or return. | 200 with the report |
| PUT /delegates | Create or replace the caller's delegate record. | 200 |
| GET /reports/{id}/audit | Read the audit trail (auditors only). | 200 with a page |

Decision request.

```json
{ "decision": "approve", "comment": "" }
```

`decision` is `approve`, `reject` or `return`. `comment` is required and not blank for `reject` and `return`.

Error envelope used by every endpoint.

```json
{
  "error": {
    "code": "E_FORBIDDEN",
    "message": "GOV-1.3 refused this decision: the approver already decided an earlier step.",
    "rule": "GOV-1.3",
    "request_id": "9f0c1c0e-6a52-4c0f-b3a6-6d3a1a2c9a10"
  }
}
```

| Code | Status | Meaning |
| --- | --- | --- |
| E_VALIDATION | 400 | The body or a field fails its rule. The message names the field. |
| E_FORBIDDEN | 403 | A governance rule or a role check refused the call. `rule` names the rule. |
| E_NOT_FOUND | 404 | The report does not exist or the caller may not know it exists. |
| E_STATE | 409 | The transition is not allowed from the current state (section 3.4). |
| E_LIMIT | 422 | The base total is above 25,000.00 and cannot be routed. |

## Conflict resolution that applies

- Section 3.3 has no legal hold field. This item adds a boolean on `report`, false by default, in a forward migration. Confirm with internal audit.
- A write failure has no code in the table of section 7.1. Answer status 500 in the envelope and put the new code in a contract pull request (DS-1.4).
