## Obligations

### architecture 6.1 What people asked for

| Id | Finding |
| --- | --- |
| BA-1 | Submitters want to start a report on a phone and finish it on a laptop. Drafts must be saved without a submit. |
| BA-2 | Managers decide in the gaps of their day. They want one inbox, the oldest report first, with the total and the submitter visible without opening it. |
| BA-3 | Finance wants one line in the ledger file per approved line item, with the cost center, so nobody splits totals by hand. |
| BA-4 | Managers on leave leave reports waiting. A delegate for a date range fixes most of it. |
| BA-5 | Submitters want to know why a report was returned. A comment is not optional on a return. |
| BA-6 | Finance wants reminders early. Two business days is their preference. |

### architecture 6.2 Edge cases the interviews surfaced

1. A single receipt can cover several line items, such as one hotel bill. The receipt belongs to the report, and the link to a line item is optional.
2. A report mixes currencies. Each line converts with the rate table. The report total is the sum of the converted lines, rounded half up to the cent after summing.
3. A returned report keeps its line items and receipts. The submitter edits and submits again, and the version number goes up.
4. A report submitted on a weekend counts its business days from the next Monday.
5. A manager who is also the submitter's friend is not a reason to skip a rule. Section 4.1 has no exceptions.
6. Finance asked for a reminder after 2 business days (BA-6). Section 3.5 says 3. The architecture document is the ground truth, so work items use 3. The next version of this document should settle the number.

### architecture 7.2 Notification event

The API puts one event on the queue for each state change. The worker turns it into an email.

```json
{
  "event_id": "string, UUID",
  "event_type": "report.state_changed",
  "occurred_at": "string, UTC timestamp",
  "report_id": "string, UUID",
  "from_state": "string, one of the states in 3.4",
  "to_state": "string, one of the states in 3.4",
  "recipient_id": "string, employee id",
  "comment_present": "boolean"
}
```

The event never carries amounts, comments or names. The worker reads those from the API with the service account when it builds the email.
